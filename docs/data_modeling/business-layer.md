The Business Data Vault (BDV) functions as an extension of the Raw Data Vault (RDV). Its purpose is to facilitate user access and reporting by applying selected business rules, calculations, logic and other query assistance functions.

Key characteristics of BDV:

-   Modeling: The BDV layer is still modeled using Data Vault style tables (often named as "business" satellite, etc.)

-   Selectivity: It is not a complete copy of all objects and data from the Raw Data Vault. Structures are created selectively, holding only data that has significant business value.

-   Optionality: Adding BDV tables is an option to the Raw Data Vault. It is not required to have a perfectly compliant Data Vault.

The Business Data Vault is utilized to achieve the following enhancements:

-   Data Quality Enhancement - It enhance quality of data by applying data quality rules and master data management rules

-   Business Rule Application - It enhances data by applying defined business rules, such as specific calculations (e.g calculating net profit or total compensation)

-   Performance Structure - It prepares structures designed to improve query performance.

##### 1.PIT - Point-In-Time table [](https://data-engineering-docs-52075d.pages.roche.com/docs/data-modeling/data-vault/business-data-vault-layer/#1pit---point-in-time-table)

A Point-In-Time (PIT) table is fundamentally a query assistant structure whose sole purpose is the improvement of performance.

The primary function of a PIT table is to store snapshots of data at a point in time. These snapshots capture all or part of the satellite data that belongs to a common parent structure. The common parent structures that PIT tables relate to include a hub, link or reference table. The specific dates used to generate these data snapshots are specified by the data consumers.

##### 2\. SLAT - Satellite Latest Table [](https://data-engineering-docs-52075d.pages.roche.com/docs/data-modeling/data-vault/business-data-vault-layer/#2-slat---satellite-latest-table)

The SLAT table (Satellite Latest table) represents a specialized form of a Point-in-Time (PIT) table. As its name suggests, the SLAT table contains only the data that is valid during the time the data is being repopulated.

Structure and Content: The SLAT usually holds data from one satellite, though it can also combine data from several satellites that share the same parent entity. The structure of the SLAT table is typically the same as originating satellite, but this similarity is not mandatory.

Population Recommendation: Because the SLAT maintains only a single snapshot of data, it is recommended to populate a temporary table first and then swap it with the target table. This method ensures that the data is continously available without any down time.

##### 3\. BRIDGE - Bridge Table [](https://data-engineering-docs-52075d.pages.roche.com/docs/data-modeling/data-vault/business-data-vault-layer/#3-bridge---bridge-table)

The Bridge Table shares a similar structure and purpose with the PIT table: to improve performance.

-   Key Difference: The difference is that a Bridge Table is designed to combine data from several different parent objects, including hubs, links and satellites.

-   Population: Bridge Tables can be populated directly using raw data or populated after PIT tables have already been created.

-   Performance Goal: They are specifically designed to improve the performance of the Data Vault concerning complex 'long chain' joins.

##### 4\. BSAT - Business Satellite [](https://data-engineering-docs-52075d.pages.roche.com/docs/data-modeling/data-vault/business-data-vault-layer/#4-bsat---business-satellite)

A Business Satellite is a data structure created after various processes have been applied, including: applying business and data quality rules and generating calculated fields such as business validity dates. There is no prescribed template for the structure of a Business Satellite or for how it should be populated. It is populated using individual processes which makes it hard to automate.

Despite the lack of a prescribed template, there are several recommendations to follow when creating Business Satellites:

-   Avoid New Entities: Do not create new entities that do not already exist in the Raw Data Vault. Instead, try to stick data to existing entities (such as Customer or Sale) to ensure the source of the Business Satellite is easily understandable.

-   Shared Utility: Create a Business Satellite only if there is a chance it will be used by more than one product; otherwise, it is better to create such a structure only in the data product layer.

-   Data Consistency: Do not truncate data. The data must be kept in a consistent state so that it can be consumed at any time.
